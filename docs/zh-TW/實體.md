# 實體

**實體**是你要追蹤變化的對象：品牌、產品、成分、話題。同一個產品在新聞、論壇、電商上的寫法都不一樣，實體表把它們對到同一個 ID，才能看出它整體的變化。

> 範例中的品牌與數字都是虛構的。

## 實體表（`實體.jsonl`）

一行一個實體。

```json
{
  "id": "product:霧光-b5-修護霜",
  "type": "product",
  "name": "霧光 B5 修護霜",
  "aliases": ["B5 修護霜", "霧光修護霜", "霧光 B5"],
  "brand": "brand:霧光",
  "category": "保養/乳霜",
  "watches": ["化妝品"],
  "status": "已確認",
  "first_seen": "2026-09-30",
  "merged_into": null,
  "note": ""
}
```

| 欄位 | 必填 | 說明 |
|---|---|---|
| `id` | 是 | `類型:簡短名稱`，建立後不改。 |
| `type` | 是 | 見下方「實體類型」。 |
| `name` | 是 | 顯示用的名稱，可以改。 |
| `aliases` | 否 | 其他寫法。標註時用來辨認。程式會把新發現的寫法加進來。 |
| `brand` | 否 | 產品所屬品牌的實體 ID。 |
| `category` | 否 | 品類，用 `/` 分層，例如 `保養/乳霜`、`哺乳/吸乳器`。 |
| `watches` | 否 | 屬於哪些關注。 |
| `status` | 是 | `待確認`、`已確認`、`忽略`。見下方。 |
| `first_seen` | 是 | 第一次在觀測中出現的日期。「新出現」就是用這個判斷。 |
| `merged_into` | 否 | 被合併時，指向保留的那個實體 ID。 |
| `note` | 否 | 你的備註。 |

## 實體類型

| 類型 | 中文 | 例子 |
|---|---|---|
| `brand` | 品牌 | 霧光、小芽 |
| `product` | 產品 | 霧光 B5 修護霜、小芽防脹氣奶瓶 |
| `ingredient` | 成分 | 泛醇、A 醇、乳油木果油 |
| `topic` | 話題 | 早 C 晚 A、親餵、無香精 |
| `service` | 服務 | 月子中心、到府清潔 |

產品的規格（容量、色號）預設**不拆**成不同實體，而是記在觀測的 `subject` 裡。只有你覺得需要分開追蹤時才拆。

## 狀態：待確認、已確認、忽略

- 標註時發現的新名稱，程式會建立一個 `待確認` 的實體，並寫進當天報告讓你看。
- `待確認` 的實體**照樣追蹤**，所以第一次出現就能被偵測為「新出現」；只是在報告裡會標示「未確認」。
- 你在報告裡選擇：
  - **確認**：變成 `已確認`。
  - **合併到…**：這其實是另一個實體的別名。
  - **忽略**：不是你在意的東西（例如活動名稱、店名）。之後不再出現在報告裡，但資料照樣保留。

## 合併

合併時，被合併的實體不刪除，只填上 `merged_into`：

```json
{"id": "product:霧光修護霜", "merged_into": "product:霧光-b5-修護霜", "...": "..."}
```

- 它的別名併入保留的實體。
- 之後重算狀態時，提到它的觀測都算到保留的實體上。
- 因為原本的 ID 還在，合併可以撤銷：清掉 `merged_into` 再重算即可。
