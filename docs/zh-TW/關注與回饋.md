# 關注與回饋

**關注**定義你要追蹤的市場範圍。**回饋**是你看每日報告時打的勾。兩者合起來，讓程式越來越知道什麼是你要的。

## 關注定義（`關注/化妝品.md`）

一個關注一個 Markdown 檔，由你撰寫。程式只會在〈相關例子〉和〈不相關例子〉兩節追加你確認過的項目，其他地方不動。

```markdown
# 化妝品（台灣）

## 範圍
台灣市場的保養品、彩妝、身體清潔與香氛。包含開架與專櫃、國際與本土品牌。

## 不要的
- 醫美療程、整形診所的廣告
- 純股價、財報新聞（除非提到具體產品）
- 抽獎、團購文

## 關鍵字
修護霜、精華液、防曬、粉底、唇膏、敏感肌、成分

## 門檻
0.45

## 相關例子
- obs:3f9a1c0e7b2d 秋冬換季，修護霜搜尋量大增

## 不相關例子
- obs:91d0aa3c7e55 某醫美診所週年慶
```

| 小節 | 用途 |
|---|---|
| `# 標題` | 關注名稱。檔名就是它的 ID。 |
| 範圍 | 一段話說明要什麼。還沒有例子時，程式用這段文字判斷相關性。 |
| 不要的 | 容易混進來但你不要的類型。 |
| 關鍵字 | 給收集器用的搜尋詞。 |
| 門檻 | 相關分數超過多少算相關，預設 0.45。 |
| 相關例子 | 你確認過相關的觀測。 |
| 不相關例子 | 你退回的觀測。 |

### 相關性怎麼算

沿用 v3 的探針：

> 探針 = 相關例子的平均向量 − 0.5 × 不相關例子的平均向量

每筆觀測的相關分數，就是它的向量和探針的相似度。剛開始沒有例子時，用〈範圍〉那段文字的向量。你每退回一筆，類似的資料就比較不會再進來。

## 每日報告（`報告/日期.md`）

報告分成四節，依重要性排列。每一行前面有勾選框，勾法統一：

- `[x]`：是，這個值得追
- `[-]`：不是，這是雜訊
- `[ ]`：不確定，先不管

```markdown
# 2026-10-13 市場變化

## 熱門（2）
- [ ] 霧光 B5 修護霜：上升，提及數是平常的 4.3 倍，論壇與電商同時上升（持續中，第 3 天）
    - 證據：[論壇貼文](https://…)、[新聞](https://…)、[蝦皮名次 3](https://…)
    <!-- chg:2026-10-13:product:霧光-b5-修護霜:上升 -->

## 事件與數值變動（1）
- [ ] 某品牌爽身粉：回收（食藥署公告）
    - 證據：[公告](https://…)

## 待觀察（3）
- [ ] 小芽防脹氣奶瓶：只有論壇上升，提及數是平常的 3 倍
    - 證據：……

## 新名稱待確認（2）
- [ ] 「雲朵霜」→ 確認為新產品
- [ ] 「霧光修護」→ 合併到：霧光 B5 修護霜
- [ ] 「週年慶」→ 忽略
```

- 每一行後面的 `<!-- … -->` 註解是程式用來對應變化 ID 的，請不要刪。
- 〈新名稱待確認〉的每一行，程式已經提議好動作（確認、合併、忽略）。打 `[x]` 就照提議做，打 `[-]` 表示提議錯了。提議錯的情況，可以直接把那行改成你要的動作再打 `[x]`。

## 回饋（`回饋.jsonl`）

下一次執行時，程式讀取報告裡的勾選，寫成回饋紀錄。

```json
{"at": "2026-10-14T06:00:00+08:00", "target": "chg:2026-10-13:product:霧光-b5-修護霜:上升", "mark": "追", "from": "報告/2026-10-13.md"}
{"at": "2026-10-14T06:00:00+08:00", "target": "product:霧光修護", "mark": "合併", "into": "product:霧光-b5-修護霜", "from": "報告/2026-10-13.md"}
```

| 欄位 | 說明 |
|---|---|
| `at` | 寫入時間。 |
| `target` | 變化 ID、實體 ID 或觀測 ID。 |
| `mark` | `追`、`雜訊`、`確認`、`合併`、`忽略`、`相關`、`不相關`。 |
| `into` | 合併時，併到哪個實體。 |
| `from` | 來自哪一份報告。 |

只追加，不修改。同一個對象有多筆紀錄時，以最新的為準。

### 回饋會影響什麼

| 你的標記 | 效果 |
|---|---|
| 對變化打 `追` | 這個實體之後的變化在報告裡排前面。它的證據觀測加進該關注的〈相關例子〉。 |
| 對變化打 `雜訊` | 證據觀測加進〈不相關例子〉，探針會避開類似的資料。這個實體不會被忽略，只是這一次不算。 |
| 確認、合併、忽略 | 更新實體表，並重算受影響的標註和狀態。 |

回饋也是之後檢驗準確度的依據：累積一段時間後，可以算出「熱門」裡有多少被你標成值得追，以及哪些門檻需要調整。
