# 觀測

一筆**觀測**就是收集器從某個來源抓到的一筆資料：一篇新聞、一則論壇貼文、一個商品頁的當天數字、一筆搜尋熱度。

> 範例中的品牌與數字都是虛構的。

## 觀測（`觀測/日期.jsonl`）

收進來就不再修改。

```json
{
  "id": "obs:3f9a1c0e7b2d",
  "source": "news",
  "site": "某新聞網",
  "url": "https://example.com/news/123",
  "published_at": "2026-10-12T21:05:00+08:00",
  "fetched_at": "2026-10-13T06:00:12+08:00",
  "lang": "zh-TW",
  "title": "秋冬換季，修護霜搜尋量大增",
  "text": "……",
  "metrics": {}
}
```

| 欄位 | 必填 | 說明 |
|---|---|---|
| `id` | 是 | `obs:` 加上 `url`、`published_at`、`text` 的雜湊。同一筆重抓會得到同一個 ID，不會重複收。 |
| `source` | 是 | 來源**類型**：`news`（新聞）、`forum`（論壇／社群）、`shop`（電商）、`search`（搜尋熱度）、`industry`（產業網站）。判斷「幾種來源」時看這個欄位。 |
| `site` | 是 | 具體網站或看板，例如 `PTT MakeUp`、`蝦皮`。 |
| `url` | 是 | 原始網址。報告裡的證據連結就用它。 |
| `published_at` | 否 | 來源上的發布時間。 |
| `fetched_at` | 是 | 收集時間。 |
| `lang` | 否 | 語言，例如 `zh-TW`、`en`。 |
| `title` | 否 | 標題。 |
| `text` | 否 | 內文。商品頁或搜尋熱度可以沒有內文。 |
| `metrics` | 否 | 數值資料，見下表。 |
| `subject` | 否 | 收集器已經知道這筆是關於哪個東西時填寫，例如商品頁的商品名稱、搜尋熱度的關鍵字。 |

### `metrics`：數值資料

數字類的來源（電商、搜尋熱度）把數字放這裡。欄位名稱固定，方便跨來源比較。

| 欄位 | 意思 | 常見來源 |
|---|---|---|
| `rank` | 排行榜名次，1 是第一名 | 電商排行 |
| `price` | 售價（新台幣） | 電商 |
| `price_original` | 原價 | 電商 |
| `sold` | 累計銷量 | 電商 |
| `reviews` | 評論數 | 電商 |
| `rating` | 平均評分 | 電商 |
| `interest` | 相對搜尋熱度（0–100） | 搜尋熱度 |
| `replies` | 回覆數 | 論壇 |
| `likes` | 按讚／推文數 | 論壇 |

商品頁的觀測範例：

```json
{
  "id": "obs:a71c22d90e4f",
  "source": "shop",
  "site": "蝦皮",
  "url": "https://example.com/item/456",
  "fetched_at": "2026-10-13T06:10:40+08:00",
  "subject": "霧光 B5 修護霜 40ml",
  "metrics": {"rank": 3, "price": 399, "price_original": 520, "sold": 15200, "reviews": 2310, "rating": 4.8}
}
```

## 標註（`標註/日期.jsonl`）

標註是程式對每筆觀測的判讀，和觀測分開存，因為實體表或關注定義一改就要重算。一筆觀測對應一行。

```json
{
  "obs": "obs:3f9a1c0e7b2d",
  "relevance": {"化妝品": 0.71, "產婦": 0.12},
  "watches": ["化妝品"],
  "mentions": [
    {"entity": "product:霧光-b5-修護霜", "text": "B5 修護霜", "sentiment": "正面"},
    {"entity": "ingredient:泛醇", "text": "維他命 B5"}
  ],
  "events": [],
  "story": "story:2026-10-12:a8e1",
  "annotated_at": "2026-10-13T06:20:00+08:00",
  "version": "標註-v1"
}
```

| 欄位 | 說明 |
|---|---|
| `obs` | 對應的觀測 ID。 |
| `relevance` | 對每個關注的相關分數（探針分數）。 |
| `watches` | 判定為相關的關注。分數超過該關注的門檻才算。 |
| `mentions` | 提到的實體。`text` 是原文寫法，用來累積別名。`sentiment` 可選：`正面`、`負面`、`中性`。 |
| `events` | 原文明確寫出的事件，見下方。 |
| `story` | 重複轉載的分組，見下方。 |
| `version` | 標註程式的版本。版本不同的標註會被重算。 |

### 事件

有些變化不是數字，而是原文直接說出來的事：新品上市、停產、回收、法規禁用、代言、得獎。這類只在**原文明確寫出**時才記，不推測。

```json
{"type": "回收", "entity": "product:某品牌-爽身粉", "text": "食藥署公告回收……", "date": "2026-10-12"}
```

事件類型：`上市`、`停產`、`回收`、`法規`、`代言`、`得獎`、`漲價`、`降價`、`缺貨`、`其他`。

### 重複轉載（`story`）

同一則消息常被很多網站轉載，或在論壇被轉貼。這些在統計時只算**一次**，否則一篇新聞稿就能讓產品看起來很熱門。

- 內容高度相似、發布時間在 3 天內的觀測，歸成同一個 `story`。
- 狀態裡的「提及數」是**不同 story 的數量**，不是觀測筆數。
- 同一個 story 出現在幾種 `source`，另外記下來，作為擴散程度的參考。
