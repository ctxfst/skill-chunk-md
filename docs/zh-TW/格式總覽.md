# 格式總覽

一個 CtxFST 資料庫就是一個資料夾。全部是純文字檔：JSONL（一行一筆 JSON）和 Markdown。不需要資料庫軟體，可以放進 git，也可以用 Obsidian 直接看報告。

## 資料夾結構

```
市場追蹤/
├── 關注/                       人寫：要追蹤的市場範圍
│   ├── 化妝品.md
│   └── 產婦.md
├── 觀測/                       原始資料，每天一個檔，只追加
│   └── 2026-10-13.jsonl
├── 標註/                       程式產生：相關性、實體、重複轉載
│   └── 2026-10-13.jsonl
├── 實體.jsonl                  實體表：程式提議，人確認
├── 狀態/                       程式產生：每個實體每天一筆快照
│   └── 2026-10-13.jsonl
├── 變化/                       程式產生：今天偵測到的變化
│   └── 2026-10-13.jsonl
├── 報告/                       程式產生：每日報告，你在這裡打勾
│   └── 2026-10-13.md
├── 回饋.jsonl                  你的標記，只追加
└── 設定.yaml                   門檻、時區、基準線天數等
```

> 資料夾和檔名可以用英文（`watches/`、`observations/`…），對照見[名詞對照](名詞對照.md)。程式兩種都認。

## 誰可以改什麼

| 檔案 | 誰寫 | 可以重算嗎 | 說明 |
|---|---|---|---|
| 觀測 | 收集器 | 不行 | 收進來就不改。這是唯一的事實來源。 |
| 標註 | 程式 | 可以 | 實體表或關注定義改了，就重算。 |
| 實體表 | 程式提議，人確認 | 不行 | 程式只新增「待確認」的實體；合併、改名由你決定。 |
| 狀態 | 程式 | 可以 | 由觀測和標註算出。 |
| 變化 | 程式 | 可以 | 由狀態算出。 |
| 報告 | 程式產生，人打勾 | 可以 | 打勾的內容在下次執行時寫進回饋。 |
| 回饋 | 你 | 不行 | 只追加。改變心意就追加一筆新的，舊的不刪。 |
| 關注定義 | 你 | 不行 | 程式只會在「相關例子／不相關例子」兩節追加你確認過的項目。 |

原則：**人寫的東西程式不改寫，程式算的東西隨時可以丟掉重來。**

## 每天執行的順序

1. **收集**：各來源的新資料寫進 `觀測/今天.jsonl`。
2. **讀回饋**：把昨天報告裡的勾選寫進 `回饋.jsonl`，並更新關注定義與實體表。
3. **標註**：對新觀測判斷相關性、找出提及的實體、把同一則消息的轉載歸成一組。
4. **狀態**：為每個相關實體算出今天的快照。最近幾天的快照也重算一次，因為有些資料會晚到。
5. **變化**：把今天的狀態和基準線比較，產生變化事件。
6. **報告**：寫出 `報告/今天.md`。

## 時間

- 每筆觀測有兩個時間：**發布時間**（來源上寫的）和**收集時間**（我們抓到的時間）。
- 狀態以**發布時間**歸到哪一天；沒有發布時間才用收集時間。
- 日期一律以 `設定.yaml` 的時區切分，預設 `Asia/Taipei`。
- 時間格式用 ISO 8601，帶時區，例如 `2026-10-13T08:30:00+08:00`。

## ID 的寫法

| 對象 | 格式 | 例子 |
|---|---|---|
| 觀測 | `obs:` ＋ 內容雜湊前 12 碼 | `obs:3f9a1c0e7b2d` |
| 實體 | `類型:簡短名稱` | `product:霧光-b5-修護霜` |
| 變化 | `chg:日期:實體:種類` | `chg:2026-10-13:product:霧光-b5-修護霜:上升` |

實體 ID 一旦建立就不改。改名只改 `name`，合併用 `merged_into`，詳見[實體](實體.md)。
